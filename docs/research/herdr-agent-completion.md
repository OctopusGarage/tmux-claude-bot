# Herdr agent completion detection

Research scope: the official `herdrdev/herdr` terminal runtime, inspected at commit `ee5bfb5041bb3e4a49d591c72308aae3c81ecdde`. This is a source inspection, not a live execution experiment. The separate `herdr-core` and desktop app can have different implementations.

## Main finding

Herdr observes an agent's operational state. It does not verify whether the requested task succeeded. Internally, the states are `Idle`, `Working`, `Blocked`, and `Unknown`; there is no internal `Done` variant. The public `done` status is `Idle` with `seen == false`, while acknowledged idle is `Idle` with `seen == true`. Therefore `done` is partly an attention indicator, not a durable success receipt. [State enum](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/mod.rs#L10-L21), [public mapping](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/app/api_helpers.rs#L96-L107).

## Detection pipeline

1. Identify the agent running in the terminal through foreground-process discovery, then inspect the terminal's live bottom buffer and OSC title/progress signals. The detection loop normally wakes every 300 ms; a pending idle transition uses 100 ms rechecks. [Loop](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/pane.rs#L945-L995), [screen inputs and publishing](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/pane.rs#L1156-L1258).
2. Evaluate provider-specific TOML rules against specified regions of that input. The matching rule with the highest priority wins; equal priority preserves the earlier match. Rules may inspect the title, progress, prompt box, or selected recent lines. A known agent with no matching rule defaults to `Idle`; an unknown agent defaults to `Unknown`. [Rule selection](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/manifest.rs#L431-L507), [fallback](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/manifest.rs#L512-L564).
3. Hold a weak `Working → Idle` transition when it lacks explicit visible-idle evidence. The initial observation starts a hold, then three confirmations are required at 100 ms rechecks; the hold has a 700 ms cap. Explicit visible idle, agent replacement, or process exit bypasses that hold. This is transition confirmation, not a general requirement for several seconds of terminal silence. [Constants and predicate](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/pane/agent_detection.rs#L5-L77).
4. Arbitrate between screen-derived fallback and integration reports. A live full-lifecycle integration suppresses ordinary screen updates unless process exit or a conflicting detected agent invalidates ownership. Otherwise, effective hook state is used when present, falling back to screen state; sufficiently fresh visible blockers can override non-full-lifecycle hook state. [Ignore predicate](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/terminal/state.rs#L843-L852), [blocker arbitration](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/terminal/state.rs#L2078-L2100), [effective state](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/terminal/state.rs#L2402-L2445).
5. Treat `Working → Idle` and `Blocked → Idle` as completion transitions. Update completion sequence and attention state, with suppression for initial process acquisition or session rebinding. An active tab with a focused or unknown-focus outer terminal suppresses completion attention, so its public status can be `idle` immediately rather than `done`. [Completion predicate](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/app/actions.rs#L22-L42), [sequence and suppression](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/app/actions.rs#L1710-L1770), [seen update](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/app/actions.rs#L1828-L1854).

## Provider-specific examples

| Agent | Working evidence | Idle/completion-side evidence | Blocked evidence |
| --- | --- | --- | --- |
| Claude Code | OSC title spinner; live turn spinner/interrupt hint; waiting for background agents; MCP tasks still running | Live prompt box beginning with `❯`; idle title; idle OSC progress | Approval forms, Bash permission dialog, MCP elicitation |
| Codex | OSC title spinner; current elapsed-time status with optional interrupt hint | Non-empty title without working spinner or `Action Required`; otherwise generic known-agent idle fallback | `Action Required` title; trust/update dialogs; live approval/question forms |

These are structural terminal patterns, not natural-language analysis of the final answer. Claude's working rules outrank its prompt-box idle rule, helping avoid classifying an always-visible input box as completion. Codex has a special exclusion for a failed reconnect that retains its elapsed timer. [Claude manifest](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/manifests/claude.toml), [Codex manifest](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/manifests/codex.toml).

Transcript/history viewers can mark `skip_state_update`, preserving the previous state instead of treating historical text as current activity. Process exit directly supplies visible `Idle`; this path does not require a successful exit code in the detection function. [Skip/process-exit handling](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/pane/agent_detection.rs#L349-L376).

## Semantic integrations

The full-lifecycle integration list at this revision is Pi, OMP, MastraCode, OpenCode, Kilo, and Kimi. Do not assume installing an integration makes all providers use semantic lifecycle detection; the source explicitly distinguishes full-lifecycle and identity-only integrations. [Authority list](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/detect/mod.rs#L330-L353).

Pi reports `working` on `agent_start` and only clears its active flag on `agent_settled` when `ctx.isIdle()` is true. Its state precedence is active blocker, active agent, then idle. This avoids confusing an individual end event with the entire agent settling. [Desired state](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/assets/pi/herdr-agent-state.ts#L178-L201), [lifecycle handlers](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/assets/pi/herdr-agent-state.ts#L243-L261).

OMP ignores duplicate/late end events and `agent_end` events with `willContinue == true`, and holds retryable failures rather than immediately publishing idle. OpenCode maps execution started to working, succeeded/interrupted to idle, and failed to blocked. Therefore even a semantic idle event need not mean task success: interruption may become idle too. [OMP end handler](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/assets/omp/herdr-agent-state.ts#L439-L465), [OpenCode events](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/integration/assets/opencode/herdr-tui-session.js#L559-L591).

## Wait semantics

`agent prompt --wait` waits for observed states rather than tracking a particular turn. If submission starts from a non-working state, it first requires an observed working or blocked state within 5 seconds, otherwise returning `agent_prompt_stalled` (or an earlier caller timeout). Its default terminal matches include `idle`, `done`, and `blocked`; `blocked` means input is needed, not successful completion. If the agent was already working, completion of that existing turn can satisfy the wait. [Explicit CLI contract](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/cli/agent/bindings.rs#L265), [activity gate](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/api/wait.rs#L244-L311), [default statuses](https://github.com/herdrdev/herdr/blob/ee5bfb5041bb3e4a49d591c72308aae3c81ecdde/src/api/wait.rs#L523-L539).

## Analysis and practical implications

- **Useful for orchestration:** combine process ownership, live UI patterns, semantic lifecycle reports, and short transition confirmation. Preserve explicit blockers and pending background activity.
- **Not an acceptance gate:** observed idle, unacknowledged done, interrupted execution, and process exit do not prove correct implementation, passing tests, clean commits, or a merged PR. Those require separate verifiable evidence.
- **False completion risk:** a newly changed terminal UI can fail to match working rules and fall through to known-agent idle. The short confirmation hold filters transient redraws but cannot repair an outdated detector. This risk follows directly from the fallback and hold logic above.
- **Attention is not execution identity:** `done` depends on seen state; session rebinding, focus, and acknowledgment affect presentation. Automated acceptance should not depend exclusively on the label `done`.
- **Wait correlation is limited:** state sequence/activity gating reduces matching pre-submission idle, but there is no turn-bound completion receipt. A robust task supervisor should bind its own task identity to explicit results and independent validation.

No product code was changed or tests executed for this source-reading investigation.
